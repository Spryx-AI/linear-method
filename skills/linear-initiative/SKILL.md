# Linear initiative

Uma página de investimento. Não é spec nem backlog. Siga `linear-write-protocol`. Não cria Project nem Issue. Leia `examples.md` antes do payload.

## Cabeça
Problema, para quem, o que o v1 valida; senão [FALTA].

## Corpo
Cabe numa tela.

### Status
definição | revisão | pronto para build

### Problema
≤5 linhas

### Hipótese
Se X então Y medido por Z

### Outcomes
Com denominador (5/7, não “a maioria”)

### Mapa de Projects
Checklist de capabilities, sem tela

### Restrições
Restrições + não-objetivos

### Sucesso
Sucesso / guardrails

Beta/rollout e teto de entitlement só se o texto trouxe.

## Cortar
Jornada, slug, RB, catálogo. Conversation: no máximo uma linha de restrição.

## Write
create/update só da Initiative. Ligar projects existentes se o usuário der os nomes; não criar filhos.

## Output (fase 1)
Draft com Team, Initiative existente, Ação create|update, seções Problema/Hipótese/Outcomes/Mapa/Restrições/Sucesso, Faltas.

Pedir: `pode criar` | `pode atualizar <id>` | `cria só a initiative` | `não grava`.
