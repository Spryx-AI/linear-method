# Linear issues

Uma issue = um comportamento observável. Contrato no Project Doc. Siga `linear-write-protocol`. Não cria Initiative nem Project Doc. Prefira poucas issues. Engenheiro pode reescrever ao pegar.

## Quando
Tickets/handoff e já existe Project/Doc. Sem project unívoco: [FALTA], não gravar.

## Título
Verbo + objeto + restrição visível.

## Corpo
Curto. Não user story, não “implementar a feature”, não recopiar catálogo, não AC “bom UX”. DES-* issue separada. Duplicata de título no mesmo project: não criar.

Milestone/relation só se o texto tiver fase real ou bloqueio óbvio. Sem 5 defaults. Sem árvore especulativa.

## Write
Issues → relations só confirmadas. Buscar título igual antes de create.

## Confirmação
`pode criar` | `cria todas` | `cria todas menos DES-01` | `cria só: OBJ-01, OBJ-02` | `não grava`.
